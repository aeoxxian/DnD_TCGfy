# DnD TCG-fy · P2 (0.3.0)

P1.1에서 새 카드의 활성 덱 자동 연결, 우측 미리보기 클릭 확대, 손패의 마우스 휠/왼쪽 드래그 탐색을 추가했습니다. 유형별 개수와 역할/유형 안내도 표시합니다. 상세 검수는 [P1.1 보고서](P11_TEST_REPORT.md)를 참고하세요.

D&D 행동 선택지를 TCG 손패로 살펴보는 Windows 오프라인 카드 보드입니다. 카드 라이브러리·필터에 범용 자원 관리와 사용 확정을 연결했습니다. 카드 선택·확대만으로는 자원이 바뀌지 않습니다. [P2 검수 보고서](P2_TEST_REPORT.md)에 검증 결과와 제한을 기록했습니다.

## 앱 실행

`release/win-unpacked/DnD TCG-fy.exe`를 실행하세요. 이 폴더 전체가 필요합니다. Node.js나 개발 서버 없이 동작합니다.

이전 실행·테스트·스크린샷 결과: [P1 보고서](P1_TEST_REPORT.md). [P0 보고서](TEST_REPORT.md)와 기존 계약 문서도 보존했습니다.

## 카드 등록과 탐색

1. 상단 **카드 등록**에서 이미지를 선택하거나, 이미지 파일을 보드에 드래그해 놓습니다. PNG/JPG/JPEG/WebP를 지원합니다.
2. 이름·유형·역할·행동을 지정합니다. 여러 장을 가져오면 이름은 개별 입력하고 나머지 속성은 공통 적용합니다. 저장 후 각 카드에서 따로 수정할 수 있습니다.
3. **고급 설정**에서 사거리·거리(ft)·태그·메모를 지정합니다. 주문 유형은 0~9 주문 레벨을 기록할 수 있습니다. 이 값으로 효과나 자원을 자동 계산하지 않습니다.
4. 활성 덱이 있으면 새 카드는 그 덱에 자동 추가됩니다. 덱이 없으면 안내 후 라이브러리에만 등록됩니다. 카드 저장 후 손패 위 휠·왼쪽 드래그 또는 격자로 탐색합니다. 카드 선택 → **크게 보기**에서 원본을 화면에 맞추거나 원본 크기로 읽을 수 있습니다. ESC는 확대창을 닫고, 다시 ESC를 누르면 선택을 해제합니다.
5. **정보 수정**에서 이름·속성·태그를 바꾸거나 이미지를 교체합니다. 카드 ID와 덱 연결, 기존 비용 정의는 유지됩니다.

한 번에 최대 100장, 파일당 32 MiB, 총 디코딩 4천만 픽셀까지 가져옵니다. 확장자뿐 아니라 실제 형식과 디코딩을 검사합니다. 여러 파일 중 잘못된 파일은 별도로 안내하고 정상 파일은 등록 폼에 넣습니다. 원본을 리사이즈하거나 덮어쓰지 않습니다. 탐색용 썸네일은 별도 캐시에 보관합니다.

이미지가 없는 카드도 이름을 입력해 저장할 수 있습니다. 이미지가 외부에서 누락되면 대체 안내를 표시하며 메타데이터와 편집 기능을 유지합니다.

**등록 해제**는 확인 후 라이브러리/덱 표시에서 제외합니다. 이미지와 카드 데이터·과거 참조는 삭제하지 않습니다. 현재 복구 UI나 미참조 원본 정리 UI는 없습니다.

## 검색·필터·태그

- 역할: 공격/치유/보호/강화/약화/유틸/소생/기타. 역할과 행동·태그는 다중 선택입니다.
- 추가 필터: 행동 경제, 유형, 사거리 종류, 공통 태그. 제목은 부분 검색하며 공백/대소문자/유니코드를 정규화합니다.
- 같은 분류 안은 **OR**, 분류 사이는 **AND**입니다. 예: `(공격 OR 치유) AND 보너스 행동 AND 원거리`.
- 필터는 카드 표시만 바꿉니다. 변경 즉시 화면에 반영하고 SQLite에 저장합니다. 재시작하면 검색어와 선택 조건을 복원합니다.
- **전체**는 역할 선택만 해제합니다. **필터 초기화**는 검색어와 모든 속성 필터를 해제합니다. 라이브러리/덱 범위와 캐릭터 선택은 유지합니다.
- 카드 편집의 태그 선택/해제는 그 카드만 바꿉니다. **태그 관리**의 공통 태그 이름 수정/삭제는 해당 태그를 쓰는 카드 모두에 적용하므로 연결 수와 영향 범위를 표시합니다. 태그 이름을 바꿔도 ID는 유지됩니다.

## 캐릭터별 덱

**캐릭터·덱**에서 이름을 입력해 캐릭터와 기본 덱을 만들 수 있습니다. 상단에서 활성 캐릭터/덱을 고르고, 전체 라이브러리에서 카드를 선택해 **활성 덱에 추가/빼기**를 누르세요. **활성 덱** 보기로 해당 덱만 펼칩니다. 여러 캐릭터가 같은 카드 정의를 공유하고 덱 구성은 독립적으로 유지됩니다.

추가 덱 생성도 지원합니다. 클래스 프리셋·능력치·캐릭터 삭제/편집은 이번 단계에서 확장하지 않았습니다. 새 프로필은 2014 규칙/레벨 1로 저장하며 P3에서 상세 설정을 연결합니다.

## 자원 설정과 사용

1. 캐릭터 선택 → **자원 관리** → **새 자원 만들기**에서 이름·단위·최대치·소유 범위와 회복 조건을 지정합니다. 템플릿만 저장하거나 현재 캐릭터에 바로 장착할 수 있습니다. 같은 템플릿을 다른 캐릭터에 장착해도 현재량은 독립적입니다.
2. 카드를 선택하고 **비용 설정**에서 사용 방식과 고정/선택형 비용, 연결 자원을 지정합니다. 여러 카드가 같은 자원을 공유하고 한 사용 방식에 여러 비용을 붙일 수 있습니다. 사용 방식·소모량은 카드 공통 정보, 자원 연결은 캐릭터별 정보입니다. 비용을 없애면 무소모 사용을 기록할 수 있습니다.
3. 오른쪽에서 예상 변경량을 확인한 뒤 **사용 확정**을 누릅니다. 하나라도 부족하면 전체 차감을 거부합니다. 부족한 카드도 펼쳐 읽을 수 있습니다. 별도 **예외 사용** 확인은 자원을 차감하지 않고 기록만 남깁니다.
4. 왼쪽에서 +/−·수동 현재량 조정·짧은/긴 휴식·새벽·수동 회복을 실행합니다. 현실 시간에 따른 자동 회복은 없습니다. 긴 휴식은 전용 규칙 우선, 없으면 짧은 휴식 규칙을 한 번 적용합니다.
5. **직전 자원 변경 실행 취소**는 카드 사용·회복·수동 변경을 역순으로 복원합니다. 다중 자원은 함께 복원하고 재시작 뒤에도 사용할 수 있습니다. 템플릿/장착/비용 등 설정 변경은 이전 기록을 되돌리지 못하는 경계입니다.

장착한 템플릿은 복제해서 편집합니다. 캐릭터별 **설정** 변경은 다른 캐릭터에 적용되지 않고, 최대치 변경 시 이미 소비한 양을 보존합니다. 연결 해제된 자원을 쓰던 비용은 재연결 전까지 사용할 수 없습니다. 기존 이미지·카드 속성·필터에는 영향을 주지 않습니다.

레벨별 슬롯 트랙은 구체적인 레벨의 일반 비용으로 사용할 수 있습니다. 12클래스 프리셋, 업캐스팅·홈브루 다운캐스팅 상세 규칙은 P3 예약 상태이며 해당 기존 옵션을 보존하고 실행은 거부합니다. 현재 설정 UI는 고정 최대치를 제공하며 레벨 표/능력치 선언형 계산 규칙의 읽기·계산 구조를 준비했습니다. 전투·피해·턴·상태이상 판정은 구현하지 않았습니다.

## 개발 환경과 명령

Windows 10/11 x64, Node.js **24.x**, npm 11.x 이상을 사용합니다. 최초 설치와 패키징 도구 다운로드에만 인터넷이 필요합니다. Sharp의 Windows native 파일이 필요하므로 optional dependencies를 생략하지 마세요.

```powershell
cd C:\Users\HIKI\Desktop\DnD_TCG-FY\DnD_TCGfy_v1_0_Codex_Handoff
npm ci
npm run dev
```

이 환경처럼 Node만 있고 npm 명령이 없으면 프로젝트 내부 부트스트랩을 사용합니다. 전역 설치 없이 npm 11.6.2를 `.tools`에 받습니다.

```powershell
.\scripts\bootstrap-npm.ps1 ci --cache .tools/npm-cache
.\scripts\bootstrap-npm.ps1 run dev
```

아래 `npm ...`도 동일하게 `.\scripts\bootstrap-npm.ps1 ...`로 대체합니다.

```powershell
npm run lint
npm run typecheck
npm test
npm run build
npm start
npm run test:e2e
node scripts/e2e.mjs --dev
npm run pack:win
$env:DND_TCG_EXECUTABLE = (Resolve-Path '.\release\win-unpacked\DnD TCG-fy.exe').Path
npm run test:e2e
Remove-Item Env:DND_TCG_EXECUTABLE
```

개발 모드는 Vite `127.0.0.1:5173`과 Electron을 함께 실행합니다. CSS는 개발 서버에서 생성한 임의 nonce로만 주입합니다. React/CSS 수정은 개발 화면에 반영되고 메인/preload 수정은 개발 명령 재실행이 필요합니다. 창을 닫으면 서버도 종료됩니다. `npm start`와 배포 exe는 빌드된 로컬 번들을 읽습니다.

E2E는 실제 Windows 창을 띄워 P0 v1 데이터 업그레이드, 테스트 이미지 20장 등록, 교체·필터·덱·드롭·태그 변경·누락 이미지·재시작·원본 해시와 P1.1 조작, P2 차감·회복·Undo·격리·중복 입력을 검증합니다. 텍스트/테두리만 있는 검수 이미지이며 사용자 삽화를 생성하지 않습니다. 모든 DB/이미지는 실행별 `artifacts/p1-e2e-*/user-data`에 격리합니다. 실제 사용자 데이터에는 접근하지 않습니다.

```powershell
npm run dist:win
```

NSIS 예상 산출물은 `release/DnD-TCG-fy-Setup-0.3.0-x64.exe`입니다. P2에서도 폴더 배포 exe를 빌드·실행했고 NSIS 설치·제거·업그레이드는 P5에서 검수합니다. 코드 서명은 없습니다.

## 데이터 위치와 호환성

배포 기본 경로는 `%APPDATA%\DnD TCG-fy`, 개발 기본 경로는 `%APPDATA%\DnD TCG-fy Development`입니다. P0와 같습니다.

```text
userData/
  data/app.sqlite3                     # SQLite v3, 도메인 데이터/필터/설정
  assets/<uuid>.png|jpg|webp            # 원본 바이트 복사본
  cache/thumbnails/<asset-id-hash>.webp # 재생성 가능한 탐색 캐시
  backups/before-v2-to-v3-<uuid>.sqlite3
  chromium/                            # 로컬 Electron 세션
```

기존 DB 마이그레이션 전 일관성 백업을 만들고 트랜잭션으로 v3를 적용합니다. 기존 카드 ID/태그 ID/캐릭터/덱/비용/자원/기록 및 P0 환경 설정을 유지합니다. 잘못된 새 입력과 지원하지 않는 미래 버전 DB를 거부하며 자동 리셋하지 않습니다. 잘못된 저장 카드 행은 경고하고 원본 행을 보존합니다.

원본 파일은 외부 경로와 분리된 복사본이므로 외부 원본을 옮겨도 앱에 가져온 이미지는 유지됩니다. 교체 전 이미지와 취소된 가져오기의 미참조 복사본도 자동 삭제하지 않습니다. ZIP 백업/복원과 보존 정책은 P5에서 다룹니다. 실행 중 DB만 복사하면 WAL의 최근 변경을 빠뜨릴 수 있으므로 수동 백업은 앱을 완전히 종료한 상태에서 userData 전체를 보존하세요.

`DND_TCG_TEST_USER_DATA`는 E2E가 지정하는 절대 경로입니다. 일반 사용에서는 설정하지 마세요. 새 v3 DB는 P0/P1/P1.1 앱으로 다운그레이드해 열 수 없습니다. 이전 앱은 미래 버전으로 거부하며 데이터를 초기화하지 않습니다.

렌더러는 Node/파일/DB를 직접 읽지 못합니다. preload의 용도별 함수만 호출하고 메인이 입력과 프레임을 검증합니다. 이미지도 asset ID로 지정한 로컬 프로토콜로만 읽습니다. 경로 순회/네트워크 경로/포맷 위장/손상/크기 초과를 검사하며 외부 연결·새 창·권한 요청을 차단합니다.

## 코드와 다음 단계

- `electron/library-store.ts`, `assets.ts`: 카드/태그/덱 트랜잭션 및 원본·썸네일 관리.
- `electron/main.ts`, `preload.ts`, `security.ts`: IPC와 로컬 전용 프로토콜.
- `src/components/`: 등록 폼, 필터, 태그/덱 관리, 원본 확대.
- `src/shared/`: 런타임 계약, 순수 필터 및 자원 계산 함수.
- `electron/resource-store.ts`: SQLite 자원 트랜잭션·요청 중복 방지·실행 취소.
- `tests/`, `scripts/e2e.mjs`: 회귀 테스트와 재현 가능한 Windows 시나리오.
- `DATA_SCHEMA_P1.md`, `DATA_SCHEMA_P2.md`, `DECISIONS.md`: 기존 계약의 호환 가능한 보충과 구현 결정.

다음 P3는 검증된 클래스 프리셋과 시전 슬롯 규칙입니다. 카드 공통 비용과 캐릭터별 연결의 버전 관리, 레벨 변경 시 소비량 보존, 시전 옵션과 일반 슬롯 트랙 구분을 먼저 설계해야 합니다. 제안과 위험은 P2 보고서에 정리했으며 이번 단계에 프리셋·시전 상세 기능을 임의 추가하지 않았습니다.
